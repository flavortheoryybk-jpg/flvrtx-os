# Contributing to FLVRTX

Thank you for contributing to FLVRTX.

This document defines the development workflow and quality standards.

---

# Before Contributing

Please read:

- Architecture
- Coding Standards
- Design System

---

# Branches

Use feature branches.

Example:

feature/cook-mode

feature/search

feature/dark-mode

---

# Commit Messages

Use Conventional Commits.

Examples:

feat: add recipe hero

fix: correct navigation

docs: update deployment guide

refactor: improve blade components

---

# Pull Requests

Every pull request should:

- Build successfully
- Follow coding standards
- Be responsive
- Avoid duplicated code

---

# Code Style

Follow:

- Blade conventions
- Tailwind standards
- WordPress coding standards
- Component-first architecture

---

# Documentation

Any major architectural change should also update FLVRTX OS documentation.

---

# Goal

Maintain a clean, scalable, and maintainable codebase.
